# context-manager

[English](README.md)

`context-manager`는 Claude Code, Codex CLI, Gemini CLI가 프로젝트 디렉터리에서 모델에게 실제로 보내는 내용을 보여 주는 실행 파일 하나입니다. 어떤 지침 파일이 어떤 순서로 불러와지는지, 토큰을 얼마나 차지하는지, 어디가 잘리는지를 보여 줍니다. 그 파일과 훅과 메모리를 직접 고칠 수도 있으며, 모든 쓰기 전에 미리 보기가 나오고 변경 기록을 되돌릴 수 있습니다.

> 스크린샷: 추후 추가합니다.

## 빌드와 설치

Rust(stable, edition 2024)와 Node.js와 pnpm이 필요합니다. 설치 스크립트는 UI를 빌드하고 릴리스 바이너리를 빌드한 뒤 `~/.local/bin`에 복사합니다. `PREFIX`에 디렉터리를 지정하면 그곳에 복사합니다. 스크립트는 `sudo`를 쓰지 않습니다.

```sh
scripts/install.sh               # 데스크톱 빌드: 창과 --serve를 모두 지원합니다
scripts/install.sh --headless    # 창이 없는 빌드: --serve만 동작합니다 (약 13.5 MB)
PREFIX=$HOME/bin scripts/install.sh --headless
```

창이 없는 빌드에는 GUI 라이브러리가 필요하지 않으므로 Linux 서버에는 이 빌드를 설치합니다. 코드가 Linux용으로 계속 컴파일되는지 확인하려면 `scripts/check-linux.sh`를 실행합니다. 프로젝트의 모든 검사를 돌리려면 `scripts/check.sh`를 실행합니다.

## 실행

```sh
context-manager                       # 현재 디렉터리를 창으로 엽니다
context-manager --path ~/work/app     # 다른 프로젝트 디렉터리를 엽니다
context-manager --serve               # 같은 UI를 127.0.0.1:7457에서 HTTP로 제공합니다
context-manager --serve --port 0      # 비어 있는 포트를 골라 씁니다
context-manager --serve --host 0.0.0.0 --port 8080
context-manager --read-only           # 모든 쓰기와 훅 실행을 거부합니다
```

`--serve`는 토큰이 붙은 주소를 출력합니다.

```
http://127.0.0.1:7457/#token=3f9c...
```

이 주소를 브라우저에서 엽니다. 토큰은 주소의 조각(fragment) 부분에 들어 있으므로 브라우저가 서버로 보내지 않습니다. 페이지는 토큰을 세션 동안 보관하고 주소창에서 지웁니다. 모든 API 요청에는 이 토큰이 필요합니다. 시작할 때마다 같은 토큰을 쓰려면 `CONTEXT_MANAGER_TOKEN`을 지정합니다.

```sh
CONTEXT_MANAGER_TOKEN=choose-a-long-secret context-manager --serve
```

서버는 암호화되지 않은 HTTP를 사용하고, 토큰을 가진 클라이언트는 그 컴퓨터에서 훅을 실행할 수 있습니다. 기본값인 루프백 주소에 바인딩하고, 원격 서버에는 SSH 터널로 접속합니다.

```sh
ssh -L 7457:127.0.0.1:7457 user@server       # 내 노트북에서 실행합니다
context-manager --serve --path ~/work/app    # 서버에서 실행합니다
```

그다음 노트북의 브라우저에서 출력된 주소를 엽니다. `--host`에 루프백이 아닌 주소를 주면 경고가 출력됩니다. 그 주소에 접근할 수 있고 토큰을 가진 사람은 누구나 그 컴퓨터에서 명령을 실행할 수 있기 때문입니다.

## 보여 주는 것과 고칠 수 있는 것

프로젝트와 홈 디렉터리에서 찾은 각 에이전트에 대해 다음을 보여 줍니다.

- **컨텍스트.** 모든 지침 파일, 규칙, 가져오기(import)를 불러오는 시점별로 묶어 보여 줍니다. 시점은 세션 시작, 에이전트가 파일을 열 때, 사용자가 호출할 때, 에이전트가 읽기로 선택할 때입니다. 세션 시작 때 모델에게 전달되는 글자 그대로의 텍스트와 합계로 계산한 토큰 예산을 보여 주고, 건너뛰었거나 가려졌거나 잘린 파일은 그 이유와 함께 보여 줍니다.
- **메모리.** 메모리 저장소와 그 항목을 보여 줍니다.
- **훅.** 모든 훅의 이벤트, 매처, 핸들러, 상태를 보여 주고, 켜고 끄는 스위치와 새 훅 양식과 시험 실행을 제공합니다.
- **확장.** 스킬, 명령, 서브에이전트를 보여 줍니다.
- **진단.** 존재하지 않는 훅 프로그램, 해석되지 않는 설정 파일, 존재하지 않는 파일로 가는 링크 같은 문제를 알려 줍니다.
- **기록.** 도구가 만든 모든 변경을 차이(diff)와 되돌리기와 함께 보여 줍니다.
- **검색과 경로 시뮬레이터.** 에이전트가 불러오는 내용을 검색하고, 에이전트가 이 경로를 열면 어떤 파일이 불러와지는지 알려 줍니다.

에이전트가 읽는 파일은 무엇이든 추가하고 고치고 지울 수 있습니다. 에이전트나 플러그인이 직접 관리하는 파일은 예외이며, 이런 파일은 이유와 함께 읽기 전용으로 열립니다.

## 쓰기를 보호하는 방법

1. **미리 보기.** 모든 편집은 먼저 계획을 세웁니다. 아무것도 쓰기 전에 정확한 차이와 모든 경고를 볼 수 있습니다. 쓰기는 계획이 미리 본 것과 같을 때만 적용됩니다.
2. **충돌.** 파일을 연 뒤에 디스크의 파일이 바뀌었다면 저장은 충돌이 되고 현재 텍스트를 보여 줍니다. 도구가 파일을 덮어쓰는 일은 없습니다.
3. **휴지통.** 삭제한 파일은 운영체제의 휴지통으로 갑니다. 데스크톱이 없는 Linux 서버처럼 휴지통이 없는 곳에서는 파일을 지우고, 그 내용은 변경 기록에 남깁니다.
4. **기록.** 변경을 적용하기 전에 도구가 이전 내용을 저장합니다. 도중에 중단된 변경은 도구가 시작될 때 마무리하거나 알려 줍니다.
5. **되돌리기.** 기록의 항목은 자체 미리 보기가 있는 새 변경으로 되돌립니다. 삭제한 파일은 기록에 저장된 사본에서 복원하므로 휴지통을 비워도 되돌릴 수 있습니다.

도구는 이 경로로만 파일을 쓰며, 사용자 대신 승인을 기록하지 않습니다. 신뢰 해시, 신뢰 파일, 확인 파일을 쓰지 않습니다.

## 훅을 끄면 일어나는 일

| 에이전트 | 도구가 쓰는 내용 |
|---|---|
| Codex CLI | 사용자 `config.toml`의 `[hooks.state."<key>"]` 아래에 `enabled = false`를 씁니다. 다시 켜면 그 키를 지웁니다. |
| Gemini CLI | `settings.json`의 `hooksConfig.disabled`에 훅의 이름을 씁니다. 이름이 없으면 명령을 씁니다. 항목 하나가 여러 훅을 끌 수 있으며, 미리 보기가 그 개수를 알려 줍니다. |
| Claude Code | Claude Code에는 끄는 기능이 없습니다. 도구가 설정 파일에서 핸들러를 지우고 자신의 데이터 디렉터리에 저장합니다. 그 훅은 꺼진 상태로 목록에 남고, 다시 켜면 원래 자리에 돌아옵니다. |

플러그인이나 관리형 설정에서 온 훅은 업데이트 때 덮어써지므로 끌 수 없습니다.

## 도구가 데이터를 저장하는 곳

플랫폼의 데이터 디렉터리에 저장합니다. macOS에서는 `~/Library/Application Support/context-manager`이고, Linux에서는 `$XDG_DATA_HOME/context-manager`(보통 `~/.local/share/context-manager`)입니다. 다른 디렉터리를 쓰려면 `CONTEXT_MANAGER_DATA_DIR`을 지정합니다. 이 디렉터리에는 `history/changes`(변경마다 JSON 파일 하나), `history/blobs`(저장된 파일 내용), `parked/`(꺼 둔 Claude Code 훅)가 들어 있습니다. 이 디렉터리는 현재 사용자만 접근할 수 있습니다. 도구는 이 밖의 데이터를 저장하지 않으며, 스캔은 파일 시스템과 환경 변수만 읽습니다.

## 무엇을 검증했고 무엇을 검증하지 못했는가

- **Codex CLI.** 설치된 CLI와 대조했습니다. 세션 시작 텍스트는 `codex debug prompt-input`의 출력과 바이트 단위로 일치하고, 훅 목록과 훅 해시는 `hooks/list`의 응답과 일치합니다.
- **Claude Code.** 설치된 실행 파일을 로컬 싱크에 대해 일곱 가지 시나리오로 실행해 대조했습니다. 설정을 바꾸는 계획을 적용할 때마다 `claude doctor`가 그 파일을 통과시킵니다.
- **Gemini CLI.** 한 번도 실행하지 않았습니다. 규칙은 v0.69.0 태그의 소스에서 가져왔고, 어댑터의 테스트는 픽스처로만 그 규칙을 확인합니다.
- **쓰기 흐름.** 헤드리스 Chrome에서 실제 UI로 시험했고, 임시로 만든 홈 디렉터리에서만 실행했습니다. 실제 에이전트 홈에서는 실행하지 않았습니다.
- **토큰 수.** o200k 토크나이저로 구한 추정값입니다. Claude와 Gemini는 다른 토크나이저를 쓰므로 실제 값은 다릅니다.
- **Linux.** 창이 없는 빌드는 `scripts/check-linux.sh`로 컴파일만 확인했습니다. Linux에서 실행한 적은 없으며, 데스크톱이 없는 Linux 서버에서 휴지통이 어떻게 동작하는지도 시험하지 못했습니다.
