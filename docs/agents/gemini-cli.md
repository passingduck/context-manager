### The tiered model in one picture

In 0.69.0 the model receives instruction files in three places (`src: packages/core/src/utils/environmentContext.ts:61-66`, comment "Tiered context model (see issue #11488)").

| Tier | What | Where it lands in the request | Loaded when |
|---|---|---|---|
| 1 | Global `~/.gemini/<names>` and private project memory `~/.gemini/tmp/<slug>/memory/MEMORY.md` | System instruction, after the base prompt | Session start; re-rendered on every memory refresh |
| 2 | Project files (`<names>` from the upward walk), extension context files, MCP server instructions | First user turn, inside `<session_context>` | Session start, new chat, compression |
| 3 | Subdirectory `<names>` found just-in-time | Appended to the result of the tool that touched the path | On demand |

### Concatenation order and separators (exact)

All of the following are CONFIRMED.

- **Per-file block** (`memoryDiscovery.ts:295 concatenateInstructions`): `--- Context from: <absPath> ---\n<content.trim()>\n--- End of Context from: <absPath> ---`. Blocks are joined with `\n\n`. Paths are absolute, with backslashes turned into `/` (`paths.ts:378 toAbsolutePath`). A file that is empty or whitespace-only after trim produces no block, but it still counts as loaded.
- **Order inside the project tier:** paths from all workspace roots are pooled and deduped by `dev:inode`. They are then sorted with JavaScript's default `Array.prototype.sort()`, which is UTF-16 code-unit order on the absolute path (`memoryDiscovery.ts:427-430`). This usually puts parents before children, but not always. `/r/B/GEMINI.md` sorts before `/r/GEMINI.md` because `B` (0x42) < `G` (0x47). `AGENTS.md` sorts before `GEMINI.md` in the same directory. A scanner must reproduce this sort and must not assume root-to-leaf order.
- **Order inside the global tier:** `<names>` order. **Extension tier:** sorted, and deduped case-insensitively (`memoryDiscovery.ts:383`).
- **Tier 1, in the system instruction** (`packages/core/src/prompts/snippets.ts:169 renderFinalShell`, `:525 renderUserMemory`; `core/src/config/config.ts:2615 getSystemInstructionMemory`). The memory text is appended after the base prompt and a blank line. Its form depends on whether private memory exists:
  - **Private memory empty:** a plain string is passed, so the "string form" is used: `\n# Contextual Instructions (<names joined ", ">)\n…precedence text…\n\n<loaded_context>\n<global blocks>\n</loaded_context>`.
  - **Private memory present:** the "object form" is used: `\n---\n\n<loaded_context>\n<global_context>\n…\n</global_context>\n<user_project_memory>\n--- Private Project Memory Index (private, not committed to repo) ---\n…\n--- End Private Project Memory Index ---\n</user_project_memory>\n</loaded_context>`.
  - **Afterwards:** runs of 3 or more newlines are collapsed to 2 (`promptProvider.ts`).
- **Tier 2, in the first user turn** (`core/src/config/config.ts:2632 getSessionMemory`; `environmentContext.ts:50`): inside `<session_context>…</session_context>`, after date, OS, temp dir and the directory tree: `\n<loaded_context>\n<extension_context>\n…\n</extension_context>\n<project_context>\n<project blocks>\n\n<MCP server instructions>\n</project_context>\n</loaded_context>`.
- **Tier 3, in the tool result** (`jit-context.ts:45-64`): `<tool output>\n\n--- Newly Discovered Project Context ---\n<blocks>\n--- End Project Context ---`. For binary or image results, the same text is added as an extra part.

## Doc drift summary (source wins; the docs were checked live on 2026-11-19)

1. `reference/configuration` "Context files": describes an eager downward scan capped at 200 directories and an upward walk to `.git` or home. In 0.69.0 there is no downward scan (JIT only), `discoveryMaxDirs` is dead, and the upward walk stops at the boundary marker, or at the workspace directory itself when there is none.
2. `cli/gemini-md`: implies `context.fileName` replaces `GEMINI.md`. It prepends, and `GEMINI.md` stays.
3. `reference/memport`: claims `marked`-based code detection and "specified directories". The source uses a backtick regex, and the allowed root is the importing file's git root or its own directory. The `@../shared/...` example works only inside a git repo.
4. `hooks` index: "warned before it executes". The warning does not block and auto-trusts. The index also omits that untrusted folders disable **all** settings-file hooks.
5. `context.loadMemoryFromIncludeDirectories` description: include directories are always scanned. The flag only controls a refresh when a directory is added mid-session.
